# Code of Conduct

## The short version

Be decent. Assume the other person is trying to help. Argue about the code, not
about the person writing it.

## What that means here

- Technical criticism is welcome and expected. Make it about the change: what it
  breaks, what it misses, what would be better. "This regex misses a subdomain" is
  useful. "This is sloppy work" is not.
- Being wrong is normal and gets written down rather than hidden. Several commits
  in this repository correct an earlier claim of mine. That is how it should work.
- No harassment, no personal attacks, no demeaning comments about anyone's
  identity or experience level.
- Someone's first contribution is the one most worth being patient with.

## Scope

This applies in the issue tracker, in pull requests, in commit messages, and
anywhere someone is representing this project.

## Enforcement

Report a problem to gosha.babakhanov@gmail.com. Reports stay private.

There is one maintainer, so expect a human reading email rather than a committee.
Responses range from a request to change the comment, through editing or removing
it, to a block. The maintainer applies this document to themselves too.
